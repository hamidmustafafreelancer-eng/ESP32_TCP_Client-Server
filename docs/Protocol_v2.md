# Custom Binary Protocol Specification v2

## 1. Overview

This document defines the application-layer binary protocol used between the ESP32 firmware and the Python server.

The protocol is designed to be:

- Lightweight
- Platform independent
- Extensible
- Easy to parse
- Suitable for embedded systems

TCP provides reliable byte transport, while this protocol defines the structure and meaning of those bytes.

---

# 2. Design Goals

- Small packet overhead
- Modular architecture
- Platform-independent serialization
- Forward compatibility
- Easy debugging
- Future protocol expansion

---

# 4. Packet Format
```
+----------+-------------+----------------+---------------+
| Type (1) | Sequence (2)| Payload Len (2)| Payload (N)   |
+----------+-------------+----------------+---------------+
```
Total Header Size = 5 Bytes

All multi-byte fields use Big Endian (Network Byte Order).

---

# 5. Message Categories

The protocol reserves message ID ranges to simplify future expansion.

| Range | Category |
|-------:|----------|
| 0x10–0x1F | Telemetry |
| 0x20–0x2F | Commands |
| 0x30–0x3F | Configuration |
| 0x40–0x4F | Device Management |
| 0x50–0x5F | Errors |
| 0x60–0x6F | Firmware Update |

---

# 6. Message Definitions

## Telemetry

Direction:

ESP32 → Server

Purpose:

Transmit information generated by the device.

Messages

0x10 SENSOR_DATA

Sensor readings

0x11 STATUS

Device operational status

0x12 EVENT

Application events

0x13 LOG

Diagnostic logging

## Commands

Direction

Server → ESP32

Purpose

Control device behavior.

Messages

0x20 COMMAND

Execute an action

0x21 COMMAND_RESULT

Execution result

0x22 COMMAND_ACK

Acknowledgement for command processing

## Configuration

Direction

Bidirectional

Purpose

Read or modify device configuration.

Messages

0x30 CONFIG_GET

0x31 CONFIG_SET

0x32 CONFIG_RESPONSE

## Device Management

Purpose

Maintain communication and identify devices.

Messages

0x40 HEARTBEAT

0x41 PING

0x42 PONG

0x43 DEVICE_INFO

0x44 VERSION

0x45 ACK

## Errors

Messages

0x50 ERROR

0x51 WARNING

## Firmware

Reserved for future OTA implementation.

Messages

0x60 OTA_BEGIN

0x61 OTA_DATA

0x62 OTA_END

0x63 OTA_STATUS

# Payload Rules

The protocol layer does not interpret payload content.

Payload format is defined by the application using the message type.

Example

Message Type:

SENSOR_DATA

Payload

Temperature  
Humidity  
Pressure 

Protocol layer treats the payload only as raw bytes.
